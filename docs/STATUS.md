## Дёрганость: три причины, все закрыты

1. 🔴 **Плёнка не работала на WebGL вообще.** `hasWebGL2()` в `App.tsx` создавал
   проверочный контекст и не отпускал его — настоящий контекст сцены после этого
   не поднимался, `FilmGL` молча уходил на запасную канву `Film.tsx`, а та
   показывает целые кадры без смешивания. Весь параллакс и реакция на курсор
   умирали на первых секундах. Теперь проверочный контекст освобождается через
   `WEBGL_lose_context`.
2. **Кадр переключался целым номером** → ступени. В шейдер добавлены `frameNext`
   и `frameMix`, соседние кадры смешиваются по дробной части позиции. Замер по
   скриншотам: было 25 застывших шагов из 40 с рывками, стало 0.
3. **Перемотка при обновлении.** Кадры грузились с нулевого, поэтому при
   обновлении на середине сцена показывала начало и догоняла на глазах. Теперь
   порядок загрузки идёт от текущей позиции в обе стороны, а `progressRef`
   считается синхронно (`initialProgress()`), плюс первый кадр берётся без
   сглаживания (`snap`).

Заодно: `onFail` уехал в ref — раньше он был новой стрелкой на каждый рендер,
и эффект отрисовки пересобирался на каждый загруженный кадр, теряя контекст.

⚠️ **Грабля тестирования:** проверять WebGL в Playwright с `--use-angle=gl`
на этой машине НЕЛЬЗЯ, пока занята видеокарта — контекст не поднимается вовсе,
и тест показывает запасную плёнку вместо живой. Прошлая запись в граблях
(«только с `--use-angle=gl`») дала ровно ложный диагноз. Проверять без флагов.

## Текст: стелется строка за строкой

`src/ui/Lines.tsx` переписан по [`LINE-MOTION.md`](LINE-MOTION.md): прокрутка
решает, какая строка уже пошла (счётчик только вперёд), сама строка играет по
времени. «Стелется» = маска раскрывает + сдвиг по ходу чтения + наклон от
скорости прокрутки с точкой отсчёта у края.

Попутно закрыты три бага, найденные разбором:
- длительность бралась в момент разбиения (прогресс ≈ 0 у всех блоков) — связка

- `mask: 'lines'` срезал верхушки букв на уровнях с межстрочным < 1 — добавлен
  `--mask-pad` и `linesClass`;
- `useGSAP` без `revertOnUpdate` не откатывал контекст, и каждая смена языка
  оставляла живой набор триггеров.

## Почему перерендер: текст не читался, и виновата была сцена

Появился измеритель — `render/check_contrast.py`. Он берёт каждый 6-й кадр,
считает яркость в зонах, куда ляжет текст, и меряет **p95, а не среднее**: один
блик от кромки блюдца среднее не сдвинет, а строку убьёт. На текущей плёнке
**провалено 7 карманов из 11**, местами втрое (p95 200 при пороге 75).

Дальше по порядку:

1. **Грейд карманов** (`render/grade_pockets.py`) — не затемнение, а компрессия
   светов внутри кармана: тёмное не трогается, блики поджимаются. Героя защищает
   карта глубины из Cycles (фон гасится целиком, передний план на 30%). Первая
   проба с растушёвкой 5,5% дала видимую вертикальную границу по центру кадра —
   поднято до 11%.
2. **Потолок затемнения** `MAX_DARKEN = 0.45`: упёрлись — значит грейд для этого
   кармана бессилен, и скрипт сам печатает список блоков, которым нужен скрим.
   Давить сильнее нельзя: там свет лежит на самой чашке.
3. **Карта пригодности** (`render/suggest_pockets.py`) показала настоящую причину:
   во второй половине ленты (налив, взгляд в чашку) тёмного поля под текст почти
   нет, а стойка светло-серая — то самое «всё серое» из претензий Томера.

Отсюда вывод: правится не текст и не подложки, а **свет сцены**. Из трёх проб
Томер выбрал **C** (глубокие тени): доля светлых пикселей падает с 20,8% до
12,1%, чашка и блюдце не тронуты — меняется только окружение.

## ✅ Закрыто: чашка двоилась

Замечание Томера вечером 14.08 — «стенки выходят из стенок» и на компьютере, и
на телефоне. Виноват был параллакс по глубине, но не там, где ожидалось.

Кадры из Cycles оказались чистыми — двоение рождалось уже в браузере. Смещение
считалось по глубине, прочитанной из карты один в один, а на силуэте глубина
прыгает сразу на всю разницу: чашка стоит на 0,4, стена за ней на 0,95. При
`PARALLAX = 0.075` это до шестидесяти пикселей, и соседние точки по разные
стороны контура уезжали в противоположные стороны — контур раздваивался, ручка
обрывалась, край блюдца превращался в пилу.

Три правки в `FilmGL.tsx`:

1. **Глубина для смещения читается сглаженной** — с четвёртого уровня
   mip-цепочки (карта 512 px → смещение считается по картинке в 32 px). Мягкость
   выбрана по нижней границе: mip 3 ещё оставлял «расчёску» на кромке чашки,
   mip 5 уже раздувал её форму. Картинка при этом остаётся резкой — сглажена
   только служебная карта.
2. **Уточняющие итерации убраны, остался один проход.** Три итерации искали
   точку, которая после смещения окажется ровно под пикселем, но у края
   предмета поиск не сходится, а прыгает между двумя ответами — отсюда и была
   поперечная рябь на ободке.
3. **Амплитуда 0.075 → 0.04**, разница глубин ограничена ±0,4. Заодно смещение
   теперь укладывается в компенсирующий зум 1.045 и не оголяет край кадра.

Отдельно — почему двоило **на телефоне**, где курсора нет: прокрутка пальцем
начинается с касания, а обработчик нажатия объявлял точку касания «курсором» и
держал её там навсегда. Теперь палец курсором не считается (`pointerType`),
волна от нажатия при этом осталась.

Проверено в настоящем браузере (Playwright, `--use-angle=gl`) на кадрах
`?shot=0` и `?shot=0.25`, курсор в обоих углах экрана — то есть при предельной
амплитуде: контуры целы, форма чашки совпадает с кадром без параллакса.

## Что изменилось в эту сессию

Два замечания Томера: на компьютере картинка замыленная, и обещанной реакции
на курсор он так и не увидел. Оба закрыты, причём вторым закрылась и старая
запись «эффект наведения не виден» из прошлой сводки.

### Резкость: две плёнки вместо одной

Плёнка рендерилась в 1100 px по ширине. Для телефона это честный размер, на
мониторе 1920 кадр растягивается почти вдвое — отсюда «замылено». Теперь:

- `public/film/` — 1100 px, телефон и планшет;
- `public/film-hd/` — 1600 px, десктоп (порог по ширине окна 900 px, `App.tsx`);
- кадр в 1600 считается ~120 с против ~50 с, вся плёнка — около двух часов.

Отдавать крупную плёнку всем нельзя: она втрое тяжелее, а на телефоне разницы
не видно.

### Реакция на курсор: сцена знает свою глубину

Прежний механизм (`bake_hotspots.py`) считал экранные позиции предметов
отдельной математикой камеры. Она была верной, но жила отдельно от кадра:
зоны разъезжались с картинкой на проценты, попасть в них курсором было почти
нельзя. Механизм **удалён вместе с `public/hotspots.json`**.

Вместо него Cycles отдаёт вторую, служебную карту — вторым проходом внутри
того же запуска Blender (`render_aux` в `scene.py`), потому что сборка сцены
дороже самого рендера, и отдельный прогон удвоил бы время плёнки:

- **R — глубина** (туман, 0 у объектива, 1 на дальнем плане);
- **G — номер предмета** (1 чашка, 2 кофе, 3 зерно, 4 питчер, 5 темпер…);
- лежит в `public/film-aux/`, 512 px, ~5 КБ на кадр, 0,7 МБ на плёнку.

Что это дало в браузере (`FilmGL.tsx`):

- **параллакс по глубине** — предметы расходятся вокруг той точки, на которую
  смотрит курсор: ближнее едет в одну сторону, дальнее в другую;
- **свет по контуру предмета** — отзывается ровно чашка, а не круг рядом;
- **пар над чашкой** — по наведению, а на телефоне сам, когда чашка в кадре
  крупно (наведения там нет, и иначе эффекта не существовало бы);
- **волна от нажатия** — идёт по поверхности от точки удара, ближнее качается
  сильнее дальнего, задетый предмет коротко вздрагивает.

Подсказка в титуле теперь разная для мыши и пальца (`cursorHint` / `touchHint`).

## Грабли этой сессии

1. **Туман в Cycles стохастический.** При одном сэмпле глубина приходит не
   числом, а шахматкой из нулей и единиц — со средним в нужной точке. Лечится
   сэмплами (64) и лёгким размытием при упаковке.
2. **Пасс Object Index приходит дырявым.** Примерно половина пикселей внутри
   предмета — нули, одинаково при 1 и 64 сэмплах, на GPU и на CPU, с фильтром
   и без. Убито полдня. Решение — не пасс, а покраска: на служебном проходе
   предметы получают плоский светящийся цвет, равный своему номеру.
3. **Фильтр пикселя нельзя схлопывать.** `filter_size = 0.01` оставлял пиксели
   без веса — маска выходила решетом. 0.5 размывает только контур.
4. **Порог шума съел пар.** `smoothstep(0.42, 0.95, …)` поверх fbm, который
   колеблется у половины: пар был написан, посчитан и невидим. Диагностика —
   вывод отдельного слоя в цвет, а не разглядывание кадра.
5. **Headless-браузер меряет не то.** По умолчанию Playwright рендерит WebGL
   на SwiftShader: 4 к/с и паника на ровном месте. Реальные числа — только с
   `--use-angle=gl`.
6. **Заливка кадра в видеопамять.** `texImage2D` каждый кадр заново выделяет
   хранилище под 1600×902; переход на `texSubImage2D` удвоил частоту кадров, а
   переход с `<img>` на `ImageBitmap` добавил остаток: 56 к/с против 39 при
   непрерывной прокрутке (сам шейдер укладывается в 60).
7. **`UNPACK_FLIP_Y_WEBGL` на ImageBitmap не действует** — сцена встала вверх
   ногами. Переворот задаётся в `createImageBitmap(blob, { imageOrientation: 'flipY' })`,
   и тогда чтение маски в JS считает строку ноль низом кадра.

## Как работать со сценой

```bash
# один кадр (быстро, для проверки)
blender -b -P render/scene.py -- --phase 0.5 --device optix \
        --out D:/tmp/test.png --samples 96 --rx 900 --ry 507

# кадр вместе со служебной картой глубины и номеров предметов
blender -b -P render/scene.py -- --phase 0.5 --device optix \
        --out D:/tmp/test.png --aux D:/tmp/test-aux --index 72

# отладочные ракурсы: --peek beans (россыпь) | --peek top (взгляд в чашку)
# свет крутится аргументами: --key 5 --rim 330 --fill 0.6 --ceil 1.4 --lamp 12 --exposure -0.22

# вся плёнка (PowerShell, переживает закрытие сессии)
powershell -File render\sequence.ps1 -Frames 144 -Out D:\tmp\cafe-hi144 `
           -Samples 112 -RX 1600 -RY 902 -Aux D:\tmp\cafe-hi144-aux -Device optix

# физика зерна
blender -b -P render/bake_beans.py -- --count 28 --frames 110 --release-every 1

# упаковка: обе плёнки и карты глубины разом
python render/pack_frames.py D:/tmp/cafe-hi144 --aux D:/tmp/cafe-hi144-aux

# публикация
GH_PAGES=1 npm run build      # затем содержимое dist → ветка gh-pages
```

⚠️ Пока идёт секвенция, `scene.py` править нельзя: Blender читает его заново
на каждом кадре, и правка попадёт в середину плёнки.

⚠️ Деплой идёт **в обход GitHub Actions** (сборка там висит в очереди с 06.08):
Pages публикуется из ветки `gh-pages`, куда кладётся содержимое `dist`. Если
страница отдаёт старое — `gh api -X POST repos/Tomer-Isr/cafe-shachor/pages/builds`.

⚠️ Проверять WebGL в Playwright только с `--use-angle=gl`, иначе меряется
программный растеризатор.
